# Developer CosmosDB Instance

Some issues can only be reproduced on real Azure CosmosDB for MongoDB — index
behavior, RU limits, sort-on-unindexed rejection, etc. This guide explains how
to use a shared dev CosmosDB account while keeping local MongoDB as the default.

## How It Works

- **Default**: local MongoDB in Docker Compose (no change from before)
- **Shared infra mode**: connects to a shared Azure CosmosDB account instead;
  the local `mongodb` container does not start (saves memory)
- **Worktree isolation**: `MONGO_DATABASE` is set per-worktree by `worktree-env`
  (e.g., `requests-db-my-feature`), so each worktree gets its own database —
  in both local and CosmosDB modes

## One-Time Setup (per team)

Deploy the shared CosmosDB account:

```bash
pnpm shared-infra:setup
# Optionally customize:
pnpm shared-infra:setup -- --resource-group my-rg --account-name my-cosmos --location westus2
```

This:
1. Deploys a **serverless** CosmosDB for MongoDB account (zero cost when idle)
2. Writes the connection string to `.env.shared-infra` in the repo base folder

The `.env.shared-infra` file is gitignored but shared across all worktrees of
the same checkout (worktrees resolve it via `git rev-parse --git-common-dir`).

## Per-Worktree Activation

```bash
pnpm shared-infra:use       # activate CosmosDB for this worktree
pnpm shared-infra:use --off # deactivate, go back to local MongoDB
```

This reads from `.env.shared-infra` in the base repo and writes `SCOPE_SHARED_INFRA=1`
plus the connection string to `.env.local` in the current worktree.

## Running

After activation, all existing commands work unchanged:

```bash
pnpm docker:dev:copilot     # uses CosmosDB, no local mongodb container
pnpm docker:dev:all         # same
pnpm docker:up:infra        # only starts redis + azurite (mongodb skipped)
```

To go back to local MongoDB:

```bash
pnpm shared-infra:use --off
pnpm docker:dev:copilot     # uses local MongoDB again
```

## How It Works (Technical Details)

1. **`scripts/dev-compose.sh`** wraps all `docker compose` calls in `package.json`
2. It sources `.env.local` and checks `SCOPE_SHARED_INFRA`
3. If `SCOPE_SHARED_INFRA=1`:
   - Does NOT add `--profile mongodb` → mongodb container won't start
   - Passes `--env-file .env.local` → compose interpolates `MONGO_CONNECTION_STRING`
4. If not set:
   - Adds `--profile mongodb` → local mongodb starts as before
   - Compose uses the default fallback: `mongodb://mongodb:27017`

The `mongodb` service is behind `profiles: [mongodb]` in `docker-compose.yml`.
All `depends_on: mongodb` entries use `required: false` so services start
without it when the profile is inactive.

## Database Naming

`MONGO_DATABASE` is in `.env.base` and gets suffixed by `worktree-env`:

| Checkout | Database name |
|----------|--------------|
| Main | `requests-db` |
| Worktree `fix-indexes` | `requests-db-fix-indexes` |
| Worktree `perf-test` | `requests-db-perf-test` |

Databases are created on first write — no pre-provisioning needed.

## Caveats

- **Serverless cold starts**: First request after idle may take 5-10 seconds
- **4000 RU/s max** on serverless: sufficient for dev, not for load testing
- **CosmosDB limitations**: Some MongoDB features aren't supported (e.g., `$lookup`
  across sharded collections). This is intentional — it's what you're testing against.
- **Migrations**: Run `pnpm migrate:up` after activation to apply migrations to
  the CosmosDB database. They handle CosmosDB-specific index requirements.

## File Layout

```
repo-base/
├── .env.shared-infra          # Connection string (gitignored, shared across worktrees)
├── infra/cosmosdb-dev.bicep   # Bicep template for the CosmosDB account
└── scripts/
    ├── shared-infra-setup.sh  # One-time Azure deployment
    ├── shared-infra-use.sh    # Per-worktree activation
    └── dev-compose.sh         # Docker compose wrapper (auto-detection)

worktree/
├── .env                       # Generated by worktree-env (has MONGO_DATABASE)
└── .env.local                 # Written by shared-infra:use (has connection string)
```
